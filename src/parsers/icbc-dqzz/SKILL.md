# icbc-dqzz：阜阳分行定期存款增长通报

两张月表（上月快照 + 本月快照）→ 8 个支行 × 4 个数的通报表，**全部照抄原表公式**，输出活公式工作簿。

**流程**：`find` 定邮件 → `fetch` 取数与识别 → `build` 出表出稿 → `send` 回信。

**一切数字都由脚本产出**：不要手算、不要手改单元格。核对看 JSON 的 `branches`、`total`、`warnings`、`notices`。

脚本：`/home/isee/.dsh/skills/icbc-dqzz/icbc-dqzz.py`（直接执行；输出 JSON）。

```bash
X=/home/isee/.dsh/skills/icbc-dqzz/icbc-dqzz.py
$X find                                   # 按约定找源邮件
$X fetch --uid UID [--uid UID ...]        # 取信 + 下载附件 + 识别上月/本月两张表
$X build --workdir DIR                    # 算数 + 出活公式工作簿 + 出正文
$X send  --workdir DIR                    # 回信（正文=文案，附件=通报表）
$X run   --uid UID [--uid UID ...]        # fetch + build，不发信
```

## 1 定邮件

**约定**：源邮件**主题含「定期」**且**当天收到**（发件人常拿附件名当主题，例如
`转发: 1月定期储蓄存款产品余额-分品种、期限时点报表0131100000-2026年01月31日`，含「定期」）。
先跑 `find`，不要自己用 `email_search` 猜。

```bash
$X find                       # 默认：关键词「定期」+ 当天收到
$X find --days 5              # 放宽回看天数（默认 3）
$X find --date 2026-10-10     # 把某天当作「今天」（补做历史；此时只看当天及更早的邮件）
```

**看 `auto` 字段决定下一步：**

- `auto: true` —— 关键词命中 + 当天 + **上月/本月两张月表都在附件里** → **直接执行**，用返回的 `uids` 接着 `fetch`。
- `auto: false` —— **不要执行**。脚本已按附件内容逐级放宽检索（窗口内关键词邮件 → 最近一天的全部邮件 →
  窗口内全部邮件），并逐封试出「最少需要哪几封」，此时把 `reason`、`proposed`、`verification`、
  `problems` 连同 `question` **讲给用户并问是否继续**；用户确认后才用他给的 uid 跑 `fetch`。
- 主题不含「定期」时（附件名也可能没带），一定走 `auto:false` 分支来请示，不是故障。

**用户直接指定了邮件** → 跳过 `find`，直接 `fetch --uid ...`。

## 2 fetch：取数 + 识别

按**内容**认表（不看文件名）：A1 含「分品种…时点报表」且能解析出「日期：YYYY年MM月DD日」、
有「合计」行 → 就是一张月表。**xlsx 与 xls 都认**（xls 用 `xlrd` 读值与格式）。

- **上个月/这个月怎么定**：本月 = A1 日期最大的一张；上月 = 日期比它小的一张里最新的那张（正常就是上月末）。
  同一天多张表按「认出的网点多 → 收到的晚」取一张；按（日期, 文件, 表名）去重，避免两封邮件重复带同一份表。
- **上月不是月末**（例如取到月中快照）会在 `notices` 里提示，此时先问用户要不要换表。
- **一张表至少要认出 10 个网点**才可用（认网点靠名称关键词，见下）。认不出的行会列进 `notices`。
- `problems` 非空 → **停下问用户**（常见：只来了一张月表、附件里没有这张报表）。
- 工作目录：`D:\资料\ICBC\automations\{收件日 YYYYMMDD}_定期存款增长`，
  内含 `source/`（原样保存附件）、`out/`、`roles.json`、`data.json`、`文案.txt`。
- **输出一律放 `D:\资料\ICBC\automations\` 下**（`DEFAULT_ROOT`）。ICBC 目录里还有别的按日期命名的工作，
  **不要**把产物写到 `automations` 外面，也不要动那些目录。

## 3 build：口径（照抄原表公式，已定稿，要改先问用户）

通报表（sheet「通报」）A 列 8 个支行 + 第 11 行合计，B~E 四列：

| 列 | 公式 | 说明 |
|---|---|---|
| B 定期余额 | `Σ 本月!{J,L,N,P,R,T,V,X,Z,AB,AD,AF,AH}行` | 本月快照的**定期**余额 |
| C 当月增量 | `Σ 本月!比年初列 − Σ 上月!比年初列` | 比年初=余额−年初，两月之差即当月增量 |
| D 当月增幅 | `=C/E` | 增量 ÷ 上月定期余额（`0.00%`） |
| E 上月余额 | `Σ 上月!{同一批 13 列}行` | 表头写成「{上月}月定期余额」 |
| 第 11 行 | `=SUM(B3:B10)` 等 | 8 个支行合计 |

- **「定期」= 整存整取（三个月/半年/一年/二年/三年/五年）+ 大额存单（一个月/三个月/半年/一年/二年/三年/五年）共 13 列**。
  活期、定活两便、通知、零存整取、教育储蓄、存本取息**都不算**。
- **支行归属**（按名称关键词认行，改名前先问用户）：

  | 支行 | 网点 |
  |---|---|
  | 颍州 | 城建、文峰、颍州营业室 |
  | 颍泉 | 颍泉营业室、牡丹 |
  | 颍东 | 颍东营业室、汇通 |
  | 界首 / 临泉 / 阜南 / 颍上 / 太和 | 各自的营业室 |

  **「安徽阜阳分行运行管理部」不计入**（原表公式也没把它算进任何支行）。
- 源表里的 `--` 按 **0** 收，千分位字符串（`1,234.56`）按数字收；数据区统一显示 `#,##0.00`。
- **输出 = 三张 sheet 的活公式工作簿**（`通报` + `{上月}月` + `{本月}月`），结构与同事的
  「M月D日月定期存款增长.xls」一致：月表里生成 20~27 行的支行汇总块（`=J6+J7+J8` 这种公式），
  通报 sheet 用公式引用它；`fullCalcOnLoad` 已置位，**Excel/WPS/LibreOffice 打开即自动重算**。
- **通报 sheet 的版式用技能内置 `assets/template.xlsx`**（字体/边框/列宽/行高/`0_ ` 与 `0.00%`
  数字格式、合计行加粗都与原文件一致；数据格留空由脚本写公式）。
  **A1 标题的日期按本月源表 A1 重写**，E2 表头按上月月份重写。
- 输出文件名默认 `定期存款增长（M.D）.xlsx`（M.D = 本月快照日），`--out-name` 可覆盖。

## 5 回信

$X send --workdir DIR --dry-run  # 只看发给谁、正文是什么

- **收件人 = 原发件人**（= 转发那张表的转发人，实测 `zhangxiang.fy@ah.icbc.com.cn`）；`--to` 可覆盖。
  多个附件分属两封邮件时，回**带本月表那封**的发件人。
- **主题**：`定期存款增长（M.D）`，M.D = 本月快照日；带 `In-Reply-To` 保持同一条会话。
- 附件只有通报表 xlsx。**用户已明确「直接发送，不用确认」**。

## 6 已知事项（改动前先问用户）

- **标题日期 = 本月源表 A1 的日期写全**（源表写着「日期：2026年10月15日」→ 标题「10月15日阜阳分行定期增长情况表」，
  若是 10月31日 就写「10月31日」）；只有解析不到日期时才退成「{M}月…」。回信主题同理用 `10.15`。
- **模板内置**：`assets/template.xlsx` 的版式取自 `10月15日月定期存款增长.xls` 的「通报」sheet。
  发件人以后若改了行名、列序、数字格式，要看新附件并**先问用户**再换内置模板。
- **活公式工作簿没有缓存值**：脚本只写公式（值由脚本另算并写进 JSON/文案），
  所以**必须用 Excel/WPS/LibreOffice 打开看数**（打开时会自动重算）；
  用 pandas/openpyxl 直接读会拿到空值，这不是出表失败。
- 同事的原文件里「10月」sheet 还留着一个 `阜阳分行` 的空标签行（第 28 行），脚本不生成它（无数据、公式也不引用）。
- **源表行序变了不用改代码**：认网点靠名称关键词，汇总块公式按实际行号生成。
  但**若某网点新增/更名/撤销**，会导致该行「认不出归属」被忽略（`notices` 会列出来）→ 先问用户再改 `BRANCH_MAP`。
