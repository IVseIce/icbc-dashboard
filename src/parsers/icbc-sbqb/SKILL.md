# icbc-sbqb：数字人民币个人钱包发展通报

明细汇总成 40 个网点的 7 个指标，覆盖进通报模板，正文按转发通报同版式回信。

**流程**：`find` 定邮件 → `fetch` 取数与识别 → `build` 填表出文案 → `send` 回信。

**一切数字和格式都由脚本产出**：不要手算、不要手改单元格。核对看 JSON 的 `warnings`、`data` 与 `totals`。

脚本：`/home/isee/.dsh/skills/icbc-sbqb/icbc-sbqb.py`（直接执行；输出 JSON）。

```bash
X=/home/isee/.dsh/skills/icbc-sbqb/icbc-sbqb.py
$X find                                   # 按约定找源邮件
$X fetch --uid UID [--uid UID ...]        # 取信 + 下载附件 + 识别角色
$X build --workdir DIR                    # 汇总 + 填表 + 出 HTML 正文与文案
$X send  --workdir DIR                    # 回信（正文=HTML，附件=通报表）
$X run   --uid UID [--uid UID ...]        # fetch + build，不发信
```

## 1 定邮件

**约定**：源邮件主题含 **「数币」/「数字人民币」/「钱包」** 且**当天收到**。
只有明细表需要从邮件拿（**网点号对照表与模板都已内置**），所以**通常一封就够**。
但现实中**源数据常与通报分两天到**，先跑 `find` 让脚本判断，不要自己用 `email_search` 猜。

```bash
$X find                       # 默认：关键词 + 当天收到
$X find --days 5              # 放宽回看天数（默认 3）
$X find --date 2026-10-10     # 把某天当作「今天」（补做历史用）
```

**看 `auto` 字段决定下一步：**

- `auto: true` —— 关键词命中 + 当天 + 拿到合格的明细表 → **直接执行**，用返回的 `uids` 接着 `fetch`。
- `auto: false` —— **不要执行**。脚本已按附件内容逐级放宽检索，**并逐封试出「最少需要哪几封」**：
  1. 窗口内主题含关键词的邮件；
  2. 最近一封带**当日快照**明细表的邮件；
  3. 最近一天收到的全部邮件；
  4. 窗口内收到的全部邮件。

  此时把 `reason`、`proposed`（含 uid/主题/日期）、`verification`、`problems` 讲给用户，
  连同 `question` 一起**问用户是否继续**；用户确认后才用他给的 uid 跑 `fetch`。

**实测（2026-10-10）**：当天只有转发的通报，明细表是前一天（10-09）到的。
窗口里还有一封**更早的 6 万多行历史堆表**（分区日期混杂 2026-05～08），
脚本会**正确跳过它**、只挑出 10-08 快照那一封（uid 1790753196）。所以当天 `find` 是
`auto:false` 但只需 **1 封** —— 这是常态，不是故障。

**用户直接指定了邮件** → 跳过 `find`，直接 `fetch --uid ...`。

## 2 fetch：取数 + 识别

按**内容**识别（不看文件名）：

| 角色 | 识别依据 | 来源 |
|---|---|---|
| `source` | 表头含 `网点号` + `钱包等级` + `注册日期`（数币明细） | 邮件附件 |
| `template` | A1 含「数字人民币个人钱包发展通报」 | 技能内置 |
| `netno` | 表头含 `支行` + `网点` + `网点号` | **技能内置**，邮件不再需要 |

- **网点号对照表已固化进技能**（`assets/netno.xls`，40 个网点，网点基本不变）。
  邮件里若还带对照表会被忽略（记在 `unknown_files`），**不需要再等那封邮件**。
- **`netno.xls` 原件是 xls(OLE2) 格式**（当初被存成 `.xlsx` 后缀），故用 `xlrd` 读。
- **模板一律用技能内置的 `assets/template.xlsx`**（用户已确认），邮件里的附件只当参考；
  它与 10.08 那封转发通报的表格逐格一致，含条件格式与配色。
- **源表必须是「单日快照」**：`分区日期` 列只允许一个值。
  历史发过跨多月的全量堆表（6 万多行、分区日期混杂），那种表**不能当日报用**
  （会把几个月的数据当成一天累计）→ 脚本判为不可用并要求另选，
  此时把 `problems` 告诉用户、请其指定正确的邮件。
- 同名角色重复时，`source` 优先取**有单一快照**的，其次快照日新的，再次行数多的。
- 工作目录：`D:\资料\ICBC\automations\{收件日 YYYYMMDD}_数字人民币钱包`，
  内含 `source/`、`out/`、`template_used.xlsx`、`roles.json`、`data.json`、`mail_body.html`、`文案.txt`。
- **输出一律放 `D:\资料\ICBC\automations\` 下**（`DEFAULT_ROOT`）。ICBC 目录里还有别的按日期命名的工作，
  **不要**把产物写到 `automations` 外面，也不要动那些目录。
- `problems` 非空 → **停下问用户**（缺明细源表、或源表不是单日快照），不要猜、不要改口径硬算。

## 3 build：汇总 + 填表

口径（**已定稿，要改先问用户**；对应同目录的 `数字人民币钱包_网点开立统计.sql`）：

| 列 | 口径 |
|---|---|
| C 一类 / D 二类 / E 三类 / F 四类 | 源表 **`钱包等级`** 列取值 1/2/3/4 的计数 |
| G 钱包开立总数 | 该网点全部行数（= 一类+二类+三类+四类） |
| H 当月新增 | 注册日期 ∈ [当月1日, 快照日] |
| I 当日新增 | 注册日期 = 快照日 |

- **等级取 `钱包等级`（第 9 列），不是 `钱包实名认证等级`（第 10 列）**。
  两列有 253 行不一致，且后者**没有任何值=1**（用它则「一类」恒为 0）。用户已明确按 `钱包等级`。
- **日期以源表「分区日期」快照为准（T-1）**，不是收信日。实测 10-09 收到的源表快照为 `2026-10-08`，
  故标题写「截至10月8日」。`data.snapshot` 就是它。
- **网点号统一 4 位**：先去掉多余的前导 0，再不足则前补 0
  （`319`/`00319` → `0319`，`555`/`00555` → `0555`，4 位原样）。
  源表导出格式变过：10-08 及以前是「不补 0」的 2~4 位，**10-09 起变成 5 位零填充**
  （`00319`/`02324`/`09558`）。`norm_netno()` 两种都要认，否则 40 个网点**一个都对不上、整表出 0**。
- 网点名对照：`网点号.xlsx` 的网点名多数不带「阜阳」，模板带 → 比对时去前缀。
  两处写法不同已内置 `TEMPLATE_ALIAS`：`颍东岳家湖支行` → 模板 `阜阳岳家湖支行`；
  `阜阳城建支行` 已带前缀。**改动前先问用户。**
- 源表中网点号不在对照表里的行（实测 `0404`/`0600`/`9558` 共 6 行，多为 2021 年历史数据）
  **按约定忽略**，会在 `warnings` 里列出。40 个目标网点每次都有数据，故不影响合计。
- **填表只写值**：模板的字体/合并单元格/列宽/**条件格式**全部原样保留。
  例外：**A1 标题的「截至X月X日」由脚本按 `data.snapshot` 重写**（只改文本）。
  模板自带的日期会过期（10-08 那次快照恰好与模板同日，把这个问题盖住了）。
- **红绿是模板自带的条件格式，不用脚本自己判断业务好坏**：
  - `G3:G42`（钱包开立总数）**top5 红底 `C00000` / bottom5 绿底 `00B050`**，
    两种底色上的数字都是**白字加粗**（dxf 里的 `theme=0` 已由脚本落成显式 `FFFFFF`，免生歧义）；
  - `I2:I1048576`（当日新增）top5 红字 / bottom5 绿字（注意这个区间**含第 43 行合计**）。
  覆盖数据后 Excel 会自动重算颜色；**并列值全部着色**（实测当日新增 27 个 0 全绿、总数并列 6 户 6 个全绿），
  与转发通报的显示一致。
  **正文内嵌的表格不再手写颜色**：`build` 直接读取刚写出的 xlsx，把条件格式
  （`cf_style_map`，按 priority 求值、并列一起着色）与静态底色（`sheet_bg_map`）照抄成 HTML，
  所以正文与 xlsx 必然一致。**改了模板的条件格式，正文会自动跟着变**，不用再改代码。

## 4 文案

脚本按数据生成（`build` 的 JSON 里给 `text`，同时写入 `文案.txt`），结构与转发通报一致：

```
截至2026年10月15日，全行累计开立数字人民币个人钱包2609户。
数币个人钱包开立总户数前3名网点为：临泉政务新区支行（596户）、颍上支行营业室（282户）、文峰支行营业室（227户）请继续保持[强][强]；后3名网点为：颍泉小隅首支行（5户）、颍东烟厂支行（7户）、颍泉人民路支行（9户）请努力追赶[加油][加油]
当日新开户前3名网点为：界首城建支行（11户）、界首科创支行（9户）、阜南百货大楼支行（8户）[强][强]；当日新增为0的网点6个[心碎][心碎]，请务必破零[拳头]。
```

- **首句不带「开户情况方面，」**，直接从「截至……」起（2026-10-16 用户定稿）。
- **网点名用完整名**（`临泉政务新区支行`、`颍上支行营业室`），只去掉「阜阳」前缀，
  **不要**缩成「颍上营业室」—— 转发通报用的是完整名。
- **并列名次按模板行序取**（用户已确认）：值相同时行号小的在前。`build` 会先把模板行序写进
  `order` 再出文案，所以脚本结果与手工通报一致，无需手改。
- **固定话术与 emoji**（2026-10-16 用户定稿，别改）：
  - 总数前3名后面接 `请继续保持[强][强]`，后3名后面接 `请努力追赶[加油][加油]`；
  - 当日新增前3名后面接 `[强][强]`；
  - 末句 `；当日新增为0的网点N个[心碎][心碎]，请务必破零[拳头]。`
- **当日新增为 0 的网点一个都没有时，末句整句去掉**（行尾就停在 `[强][强]`，不加句号、不留分号）。
- **默认照用**，只允许微调措辞；所有数字、名次一律用脚本结果。
- **改了文案要同时重写 `文案.txt` 与 `mail_body.html`**，`send` 发的是这两个文件。
  正文 HTML 里这三段与 `文案.txt` 逐字一致，前3名红色加粗、后3名绿色加粗，
  emoji 与「请继续保持」等话术放在色块**外面**（正常黑色）。

## 5 回信

```bash
$X send --workdir DIR            # 直接发
$X send --workdir DIR --dry-run  # 只看发给谁、正文是什么
```

- **收件人 = 原发件人**（暂定只回发件人，`FIXED_RECIPIENTS` 留空，不额外追加人）。
  发件人 = 转发那封通报的人（实测 `zhangxiang.fy@ah.icbc.com.cn`）。`--to` 可覆盖。
- **主题**：`数字人民币个人钱包发展通报（M.D）`，如 `数字人民币个人钱包发展通报（10.8）`。
  日期用**快照日的月.日**。带 `In-Reply-To` 保持同一条会话。
- **正文必须保留全部格式**，完全参照转发通报：
  - 仿宋_GB2312、16pt、段落 `text-indent:2em`；
  - 前3名**红色** `#FF0000` 加粗、后3名**绿色** `#00B050` 加粗；
  - **正文内嵌一份表格**（HTML），**逐格照抄出表**（值 + 静态底色 + 条件格式求值结果）：
    表头深红底白字、支行合并列、隔行浅灰、合计行浅红底 `#F9E7E7` 配 `#8B1420` 字、
    钱包开立总数前5红底/后5绿底（白字）、当日新增前5红字/后5绿字。
  - 正文用 `multipart/alternative`（纯文本 + HTML），附件为通报表 xlsx。
- 发完把 `sent` 里的收件人、主题、附件名回报给用户。

## 6 已知事项（改动前先问用户）

- **「截至」日期 = 源表快照日（T-1）**，取自 `分区日期` 列；标题与文案都用它。
  若当天没拿到源表、或快照日期异常，先问用户再定。
- **源数据常与通报分两天到**，`find` 因此多为 `auto:false`，属常态；但**只要 1 封明细表**。
- **模板内置**：`assets/template.xlsx` 取自 10.08 转发通报的附件（9 列带「支行」合并列）。
  若发件人以后改了模板结构（行名、列序、条件格式），要看邮件附件并先问用户再更新内置模板。
- **网点号对照表内置**：`assets/netno.xls`（40 个网点，8 个支行）。
  用户已明确「网点号基本不变、以后邮件也不发」，所以固化进技能、**不再从邮件取**。
  原件是 xls(OLE2) 伪装成 `.xlsx`，脚本用 `xlrd` 读。
  **若哪天网点有增减/更名**，让用户给新的对照表并更新这个文件（同时检查 `TEMPLATE_ALIAS`）。
- **源表必须单日快照**：跨多月的全量堆表（分区日期混杂）会被判为不可用并报 `problems`，
  此时**停下来问用户**要当日快照表，不要拿堆表硬算。
- **源表两列等级易混**：`钱包等级`(1~4，含一类) vs `钱包实名认证等级`(无 1)。
  仅当用户明确改口径才切到后者。
- 当日报表行数：40 个网点 + `合计` 行（第 43 行，B~I 为 `SUM` 公式，脚本不动）。
