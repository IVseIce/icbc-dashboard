# icbc-xsfw：网点线上服务能力提升通报

工行阜阳分行「网点线上服务能力」提升通报的每日流程：
**取信 → 识别源表 → 计算 → 出通报表 → 出文案 → 回信**。

**流程**：`find` 定邮件 → `fetch` 取数与识别 → `build` 出表出文案 → 微调文案 → `send` 回信。

**一切数字和格式都由脚本产出**：不要手算、不要手改单元格。核对看 JSON 里的 `warnings` 与 `data.json`。

脚本：`/home/isee/.dsh/skills/icbc-xsfw/icbc-xsfw.py`（直接执行；输出 JSON）。

```bash
X=/home/isee/.dsh/skills/icbc-xsfw/icbc-xsfw.py
$X find                                   # 按约定找源邮件（主题关键词 + 当天收到）
$X fetch --uid UID [--uid UID ...]        # 取信 + 下载附件 + 识别角色
$X build --workdir DIR                    # 计算 + 出表 + 出文案
$X send  --workdir DIR                    # 回信（正文=文案，附件=通报表）
$X run   --uid UID [--uid UID ...]        # fetch + build，不发信
```

## 1 定邮件

**约定**：源邮件主题含**「线上服务」**，且**当天收到**。先跑 `find` 让脚本判断，
不要自己用 `email_search` 猜。

```bash
$X find                       # 默认：主题关键词「线上服务」 + 当天收到
$X find --days 5              # 放宽回看天数（默认 3）
$X find --date 2026-09-28     # 把某天当作「今天」（补做历史用）
```

**看 `auto` 字段决定下一步：**

- `auto: true` —— 约定命中（关键词 + 当天）**且附件齐全 → 直接执行**，
  用返回的 `uids` 接着跑 `fetch`，不要再去问用户。
- `auto: false` —— **不要执行**。脚本已按附件内容放宽检索（窗口内关键词邮件 →
  最近一天的全部邮件 → 窗口内全部邮件），挑出能凑齐的最少几封。此时：
  1. 把 `reason`（为什么不合约定）、`proposed`（建议采用哪几封：uid + 主题 + 日期）、
     `verification.roles`（每张源表来自哪个文件、数据日期）讲给用户；
  2. 把 `question` 一并转述，**问用户是否继续、以哪几封为准**；
  3. 用户确认后才用他给的 uid 跑 `fetch`。
  - `missing_roles` 非空 = 放宽检索也凑不齐，提醒用户确认源邮件是否已到。

**用户直接指定了邮件** → 跳过 `find`，直接 `fetch --uid ...`。

**邮件封数不重要**：主邮件、补充邮件、或者全部附件挤在一封里，都直接把 uid 一起传给 `fetch`。
判定只看**附件**，不看封数：

- 必需 6 个：到店客群表×2、客户经理明细 CSV×3、营销授权通报×1。
- 可选 1 个：汇总通报表样式。**邮件带了就用邮件里的**（发件人可能改了行名/结构），
  没带就用技能内置的 `assets/template.xlsx`，并自动把标题日期改成业务日 —— 不影响出表。
- CSV 那 3 个可能和主表同封，也可能分散在后续几封（主题就是 CSV 文件名）。
- 少给 uid 只会表现为「缺少某个附件」，脚本按附件说事，不会因为封数拒绝你。

**该停就停**（`fetch` 的 `problems` 非空时不要往下做）：

- 缺少特定附件（如没有跨月的 CSV → 算不出当月添客）。
- 总附件数对不上、或某个表格附件认不出是哪张源表（`unknown_files`）。

把 `problems` 原样告诉用户并问清楚，**不要猜、不要换口径硬算**。

## 2 fetch：取数 + 识别

```bash
$X fetch --uid 1469585886 --uid 1469585887
```

附件按**内容**识别（不看文件名，文件名每天略有差异，(1) 后缀、时间戳都会变）：

| 角色 | 识别依据 | 用途 |
|---|---|---|
| `donghu_day` / `donghu_prev` | A1 含「到店客群…动户率」，按 B2 的「日期：」取最新/次新 | B、C 列 |
| `staff_cur` | CSV 第 1 行有「查询日期」，表头含`客户总数`+`合计认证好友数(去重)`，取日期最新 | D、E、F、G 列 |
| `staff_prev` | 同上，其余里面日期最新的 | F 列基准 |
| `staff_month` | 同上，**查询日期落在一个月以前**的那份 | G 列基准 |
| `auth` | 表头是 `zhihang/wangdian/khs/qys/ghs/ghqys` | H、I、K、L 列 |
| `template` | A1 含「网点线上服务能力」+「提升通报」，且**数据区是空的**。**可选** | 输出模板（行名/标题/格式） |

- 工作目录：`D:\资料\ICBC\automations\{收件日 YYYYMMDD}_网点线上服务能力提升通报`，
  内含 `source/`（原始附件）、`out/`（通报表）、`roles.json`、`data.json`、`文案-MMDD.txt`。
- **输出一律放 `D:\资料\ICBC\automations\` 下**（`DEFAULT_ROOT`）。
  ICBC 目录里还有别的按日期命名的工作，**不要**把产物写到 `automations` 外面，
  也不要动那些目录。`--root` 可改根目录，但默认不要改。
- 工作目录日期用**主邮件的收件日**；通报表标题与文件名沿用**模板自带的**（如（09.27））。
- 已填过数的通报表会被认成 `filled_report` 并**忽略**（`notices` 里列出），不会误当模板。
- 邮件没带模板 → `notices` 里会说明「使用内置模板兜底」，标题日期取**业务日**
  （`staff_cur` 的查询日期，即 09.27 这类），文件名随之生成，不阻塞流程。
  此时留意 `notices`，若发件人其实改了模板结构，要提醒用户下次把模板附上。
- `problems` 非空 → **停下问用户**，不要猜、不要改口径硬算。常见：缺当月基准 CSV、
  两个到店客群表只来了一张、某个表格附件认不出是哪张源表。
- 输出时 A/N 列行名统一改成**现名**（`ROW_RENAME`）：颍上路→岳家湖、界首影剧院→界首科创。
  进来的模板如果还是旧名，照样能匹配，输出会换成现名。

## 3 build：算 + 出表 + 出文案

```bash
$X build --workdir "/mnt/d/资料/ICBC/automations/20260928_网点线上服务能力提升通报"
```

口径（**已定稿，要改先问用户**）：

| 列 | 口径 |
|---|---|
| B 当日动户率 | (表45.I×表45.B − 表44.I×表44.B) ÷ (表45.B − 表44.B) |
| C 当月动户率 | 表45.I |
| D 添客总数 | 当日 CSV`客户总数`（按`机构名称`汇总到网点） |
| E 实名率 | 当日 CSV`合计认证好友数(去重)` ÷ `客户总数` |
| F 当日添客 | 当日 − 上一日 CSV`客户总数` |
| G 当月添客 | 当日 − 上月末 CSV`客户总数` |
| H/I/K/L | 营销授权通报 C/D/F/G |
| J / M | I÷H / **L÷K**（不是 K÷L） |

- **到店客群表的 B 列是「当月累计」**，当日到店客户数必须用两表相减，不能直接取表内 B 列。
- **当日到店 < 5 人 → B 列写「轮休」**，不算动户率、不参与排名。
  （法定节假日判别尚未启用，`HOLIDAYS` 常量留空。）
- 合计行：B/C 走两表「合计」行；D~L 取 40 个网点之和；E 按 Σ认证÷Σ添客加权。
- 网点归属 `BRANCH_MAP`（颍州7、颍泉7、颍东6，界首/临泉/阜南/颍上/太和各4，共 40）。
  模板行名与源表名的差异在 `TEMPLATE_ALIAS` 与 `short_of()` 里，改之前先问用户。
- 格式：全表微软雅黑 11；B~M 每列前 5 标红、后 5 标绿（数值不足 10 个时红色优先，如 9 个值 → 红5绿4）；
  「轮休」居左居中、不参与排名。

## 4 文案

脚本按模板套数生成，`build` 的 JSON 里直接给 `text`。**默认照用**，只允许微调措辞；
数字、排名、家数一律用脚本结果。模板（**2026-10-13 版**，示例为 10-12 数据）：

```
10月12日，全行当月到店客户手机银行动户率39.53%，当日企微添客191户，全量客户营销授权率32.55%。

到店动户率方面，阜南北城68.32%领跑[强][强]，阜南胜利路62.07%、界首科创59.96%表现靠前；人民路10.73%、烟厂12.51%排名靠后[加油][加油]

企微添客方面，阜南百货大楼24、颍东营业室22、太和营业室20当日领先全行。颍上营业室-3、颍上北关-2、颍上管仲-2暂时落后[心碎][心碎]

营销授权方面，阜南百货大楼26.38%、阜南营业室27.37%签约率垫底；颍上营业室55.05%、颍上十字街57.60%管户签约率靠后。请各支行持续抓好存量客户签约转化[加油][加油]
```

- 四段：总体 → 到店动户率 → 企微添客 → 营销授权。保持这个结构、篇幅和 emoji。
- **第一段三个指标**（均为全行口径，取自 `data.json` 的合计行）：
  当月动户率 `C`、**当日**企微添客 `F`、营销授权率 `J`。
  （旧版为「当日到店客户净增 X 人」，已于 2026-10-13 按用户要求替换。）
- **第三段改为「当日」添客**：取 `F` 列**最高 3 家**（`当日领先全行`）与**最低 3 家**
  （`暂时落后`）；并列时按模板行序，落后段不反转。旧版用的是 `G`（当月添客）与 [烟花]。
- 第二段与第四段口径不变；第二段样本不足 5 家时自动退回「当月动户率」。
- 网点简称：`X支行营业室`→`X营业室`，其余去掉「支行」（师范学院、城建、太和大桥…）。
- `notes` 里有说明时按说明调整。
- **改了文案就要重写 `文案-MMDD.txt`**，`send` 发的是这个文件。

## 5 回信

```bash
$X send --workdir DIR            # 直接发
$X send --workdir DIR --dry-run  # 只看发给谁、正文是什么
```

- **收件人 = 原发件人 + 三个固定邮箱**（脚本 `FIXED_RECIPIENTS` 自动合并去重）：

  | 固定收件人 |
  |---|
  | `zhaili.fy@ah.icbc.com.cn` |
  | `zhangxiang.fy@ah.icbc.com.cn` |
  | `yaohongcheng.fy@ah.icbc.com.cn` |

  发件人本身就是这三个之一 → 只出现一次，总共 3 个收件人；发件人是名单外的人 → 4 个。
  去重不分大小写。**不要手写收件人**，脚本已经算好，`--dry-run` 的 `to` 就是最终名单。
- 主题**统一为 `线上服务_YYYYMMDD`**（YYYYMMDD = 通报日期，如 `线上服务_20260928`），
  不再沿用原邮件主题。`--subject` 可覆盖。带 `In-Reply-To` 保持同一条会话。
- 正文 = 当日文案，附件只附通报表 xlsx。用户已明确「直接发送，不用确认」。
- 发完把 `sent` 里的收件人、主题、附件名回报给用户。

## 6 已知事项（改动前先问用户）

- **模板行名已统一为现名**（2026-09-28 起）：颍上路→岳家湖、界首影剧院→界首科创。

  实际是那几天的增量，不是严格意义的「当日」。`build` 的 JSON 里有 `staff_dates` 可核对。
