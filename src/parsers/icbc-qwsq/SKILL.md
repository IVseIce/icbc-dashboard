# icbc-qwsq：企业微信社群运营与质效评价行动推动情况通报

本地导出表（同一文件名、每次覆盖）→ 备份打戳 → 本周 vs 上周 → 覆盖进 9 列通报模板 →
生成与 **10.19 定稿邮件**同版式的 HTML 正文 → SMTP 直发张希昂。

**流程**：`status` 看家底 → `backup` 备份 → `build` 汇总出表出正文 → `send` 发信（`run`/`all` 串起来）。

**一切数字和格式都由脚本产出**：不要手算、不要手改单元格、不要手写表格 HTML。
核对看 JSON 的 `warnings`、`totals`、`text`。

脚本：`/home/isee/.dsh/skills/icbc-qwsq/icbc-qwsq.py`（直接执行；输出 JSON）

```bash
X=/home/isee/.dsh/skills/icbc-qwsq/icbc-qwsq.py
$X status                                  # 源表 / 备份清单 / 模板 / 收件人
$X backup  --date 20261026                 # 成员群聊数据统计.xlsx -> 成员群聊数据统计20261026.xlsx
$X build   --date 20261026                 # 汇总 + 出通报 xlsx + mail_body.html/txt
$X send    --date 20261026 [--dry-run]     # 新建邮件发给张希昂
$X run     --date 20261026                 # backup + build（不发信）
$X all     --date 20261026                 # backup + build + send
```

`--root` 可改工作根目录（默认 `D:\资料\ICBC\20260929企微`），测试时指向临时目录即可。

## 1 定文件

| 角色 | 路径 | 说明 |
|---|---|---|
| 源表 | `企微导出表\成员群聊数据统计.xlsx` | 企微每天**覆盖**写同一个文件，跑完就没了 |
| 备份 | `企微导出表\成员群聊数据统计{YYYYMMDD}.xlsx` | `backup` 生成；**本周 = 当日备份，上周 = 小于当日的最新一个备份** |
| 模板 | 技能内置 `assets/template.xlsx` | 取自 10.19 定稿附件（9 列、8 支行、含条件格式） |
| 方案 | 技能内置 `assets/企业微信社群运营与质效评价方案.docx` | 发信附件，照 10.19 邮件里的原件 |
| 成品 | `企微社群数据统计通报（M.D）.xlsx` | 放工作根目录（与 10.19 同规则） |
| 中间件 | `automations\{YYYYMMDD}_企微社群\` | `mail_body.html`、`mail_body.txt`、`data.json` |

**备份三态**：无 → 复制；有且 SHA256 相同 → 跳过（`skipped: true`）；
有但内容不同 → **报错停下**（说明源表又被覆盖过），问用户怎么处理，不要自动覆盖。

**首次运行没有上周备份**：脚本报错并提示用 `--prev-file` 指定（例如
`--prev-file 企微导出表\成员群聊数据统计1005-1011.xlsx`）。**此时先问用户确认上周用哪份**，
再带 `--prev-file` 重跑，不要自己猜。

## 2 汇总口径（已定稿，要改先问用户）

源表 `result` 工作表，按 `部门` 末级映射到 40 个网点，逐人累加：

| 列 | 口径 |
|---|---|
| B 群数量 | Σ`群总数` |
| D 客户数 | Σ`群成员总数` |
| F 交互数 | Σ`群聊消息总数` |
| H 熟识率 | Σ`发过消息的群成员数` ÷ Σ`群成员总数` |
| C/E/G/I | 同名指标 − 上周值 |

（用 10月9日、10月19日两次数据反验过：与历史通报逐格吻合。）

**部门映射（`DEPT_ALIAS`）**，两条是企微里部门设置错了，必须照表纠正：

- `界首影剧院支行` → `阜阳界首科创支行`
- `阜阳颍上路支行` → `阜阳岳家湖支行`
- `阜阳文峰支行` / `阜阳文峰支行营业室` → `阜阳文峰支行营业室`（文峰并入颍州支行）

**忽略**（`IGNORE_MARKS` + 空部门）：分行本部各部室、各支行机构本部/行长室/综合部，
以及 `部门` 为空的行（离职/注销账号）。10.19 那次是 37 + 3 人。
落不上的新部门会进 `warnings.unknown_dept`，**非空就先问用户**，别硬塞。

支行维度 = 同支行网点相加；8 个支行，文峰在颍州名下（7 个网点）。

## 3 填表

- 打开内置模板，两张子表（`支行维度` 12 行、`网点维度` 44 行）**只写值**：
  字体/合并/列宽/隔行底色/**条件格式**全部原样保留。
- A1 标题按日期重写：`企微个微社群数据统计表（M月D日）`。
- **合计行**：B/D/F 保留模板公式（`=IF(COUNT(...)=0,"",SUM(...))`）；
  C/E/G/I 写增量、H 写 `Σ发过消息/Σ群成员总数`、I 写熟识率差。
- 支行表行名为 `颍州支行`…（带「支行」），网点表为完整网点名，脚本会断言模板行序没变。

## 4 正文（与 10.19 定稿逐字同版式）

`build` 同时产出 `mail_body.html`（发信正文）与 `mail_body.txt`（纯文本备选）。

- 仿宋_gb2312、16pt（`21.3333px`）、`line-height:1.7`、`text-indent:42.6666px`；
  首段前额外 4 个 `&nbsp;`，段间用空段落隔开。
- **好的标红 `#FF0000`、差的标绿 `#00B050`**（与模板条件格式同向），
  标签词（`建群方面：`/`添客方面：`/`交互方面：`/`客户熟识率方面：`/`工作提示：`）加粗。
- 段落顺序（照定稿，**不要自行合并/拆分**）：
  1. 空段
  2. `截至YYYY年M月D日，全行企微累计建群G个，较上周增加/减少X个；客户数C户，较上周…`
  3. 空段
  4. 建群·支行（前2红、后2绿）
  5. 建群·网点（前3红用**简称**，未建群网点绿，N个）
  6. 空段
  7. 添客·支行（前2红、后2绿，写「存量+较上周新增/减少」）
  8. 添客·网点（前3红、后3绿）
  9. 空段
  10. 交互·支行 + 交互·网点前3（网点后3不列）
  11. 空段
  12. 熟识率·支行 + 熟识率·网点前3（网点后3不列）
  13. 空段 → 支行表 → 两个空段 → 网点表 → 空段
  14. 附件名 → 空段 → 工作提示（1 个标题段 + 2 个要点段）→ 两个空段
- **两张表由脚本现读刚写出的 xlsx 渲染**（值 + 静态底色 + 条件格式求值），
  所以正文与附件必然一致；**改了模板条件格式，正文自动跟随，不用改代码**。
- 条件格式求值规则：前 N 红 / 后 N 绿，**并列全着色**；
  网点 N=5、支行 N=3；E 列落底色 + 白字，H 列只落字色。
- 百分数按 **Excel 口径四舍五入**（`3.125%` → `3.13%`，不是 Python 的银行家舍入）。
- 负数增量写成「较上周减少X」，「未建群/为0/偏低」这类补充句按数据自动出（没有就省略）。

两份参考件在 `assets/`：`reference_body.html` 是 10.19 定稿正文原件，
改版式时拿它逐段比对。

```bash
$X send --date 20261026
```

- **收件人固定 `zhangxiang.fy@ah.icbc.com.cn`**（`--to` 可覆盖）。
- **新建邮件**（不挂原会话），主题 `企业微信社群运营与质效评价行动推动情况通报（M.D）`；
  日期用**业务日期**（`--date`），不是收信日。
- 正文 `multipart/alternative`（纯文本 + HTML），正文即 §4 的 html。
- **附件两个**：当次 `企微社群数据统计通报（M.D）.xlsx` + 内置 `方案.docx`。

## 6 已知事项（改动前先问用户）

- **源表是覆盖式**：一旦被新的覆盖，旧数据只能靠备份。`backup` 必须在取数当天先跑；
  `run`/`all` 已内置这一步。**发现当日备份已存在但内容不同就停下问用户**，别覆盖。
- **上周 = 小于当日的最新备份**。跳周（比如停了一周）时它会自动取「上一份」，
  脚本会在 JSON 里回 `prev_file`，**回报给用户确认**口径对得上。
- **建群·网点前三用简称**（不带「阜阳」）、其余网点名用全称——这是照 10.19 定稿的写法，
  不是 bug；要统一成全称，改 `short_name()` 的调用处即可（先问用户）。
- **正文里的附件名前缀是 📎**；10.19 原件用的是客户端私有字形（`\uea63`），
  收发两端显示等价，不用改。
- **模板内置**：`assets/template.xlsx` 取自 10.19 定稿附件。若发件人以后改了列结构、
  支行数或条件格式，**先问用户**再替换这个文件；正文表格会自动跟着新模板走。
- **方案 docx 内置**：`assets/企业微信社群运营与质效评价方案.docx`。方案更新时替换即可，
  文件名要保持一致（正文里会引用它）。
- **工作提示两段是固定话术**（分类建群添客的目标 + 「1+4+X」运营分工），与数据无关；
  要改措辞，改 `build_body()` 里那两句，**先问用户**。
- 部门映射表 `DEPT_ALIAS` 是固定字典；**网点增减/更名**时更新它和 `NP_BRANCH`，
  并同步检查模板行序（脚本会断言）。
