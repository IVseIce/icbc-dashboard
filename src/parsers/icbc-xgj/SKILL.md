# icbc-xgj：工银薪管家「聚薪行动」日通报

四张源表读两个数，填进通报的支行/网点两个 sheet —— **一比一映射，不做任何计算**。

**流程**：`find` 定邮件 → `fetch` 取数与识别 → `build` 填表出文案 → `send` 回信。

**一切数字都由脚本产出**：不要手算、不要手改单元格。核对看 JSON 里的 `totals` 与 `warnings`。

脚本：`/home/isee/.dsh/skills/icbc-xgj/icbc-xgj.py`（直接执行；输出 JSON）。

```bash
X=/home/isee/.dsh/skills/icbc-xgj/icbc-xgj.py
$X find                                   # 按约定找源邮件
$X fetch --uid UID [--uid UID ...]        # 取信 + 下载附件 + 识别四张源表
$X build --workdir DIR                    # 填表 + 出文案
$X send  --workdir DIR                    # 回信（正文=文案，附件=通报）
$X run   --uid UID [--uid UID ...]        # fetch + build，不发信
```

## 1 定邮件

**约定**：源邮件主题含关键词 **「薪管家」**，且**当天收到**。先跑 `find`，不要自己用 `email_search` 猜。

```bash
$X find                       # 默认：关键词「薪管家」+ 当天收到
$X find --days 5              # 放宽回看天数（默认 3）
$X find --date 2026-09-30     # 把某天当作「今天」（补做历史用）
```

**注意现实情况**：发件人（翟理）习惯**用文件名当邮件主题**，实测出现过 `网点 年`、`支行 月维度`
这类主题 —— **都不含「薪管家」**。所以 `find` 多半会走「不合约定」分支，
靠**附件内容**检索出正确邮件后向你请示。这不是故障，按下面 `auto: false` 处理即可。

**看 `auto` 字段决定下一步：**

- `auto: true` —— 约定命中（关键词 + 当天）**且四张源表齐全 → 直接执行**，
  用返回的 `uids` 接着跑 `fetch`，不要再去问用户。
- `auto: false` —— **不要执行**。脚本已按附件内容放宽检索（窗口内关键词邮件 →
  最近一天的全部邮件 → 窗口内全部邮件），挑出能凑齐的最少几封。此时：
  1. 把 `reason`（为什么不合约定）、`proposed`（建议采用哪几封：uid + 主题 + 日期）、
     `verification.roles`（每张源表来自哪个文件）讲给用户；
  2. 把 `question` 一并转述，**问用户是否继续、以哪几封为准**；
  3. 用户确认后才用他给的 uid 跑 `fetch`。
  - `missing_roles` 非空 = 放宽检索也凑不齐，提醒用户确认源邮件是否已到。

**用户直接指定了邮件** → 跳过 `find`，直接 `fetch --uid ...`。

- 工作目录：`D:\资料\ICBC\automations\{收件日 YYYYMMDD}_薪管家`，
  内含 `source/`、`out/`、`roles.json`、`文案.txt`。
- **输出一律放 `D:\资料\ICBC\automations\` 下**（`DEFAULT_ROOT`）。
  ICBC 目录里还有别的按日期命名的工作，**不要**把产物写到 `automations` 外面，
  也不要动那些目录。`--root` 可改根目录，但默认不要改。

## 2 fetch：取数 + 识别

```bash
$X fetch --uid 1469585894 --uid 1469585896
```

**四张源表长一个样**（同一个 sheet 名 `工银薪管家数据增量表`、同一套表头），
靠内容两个维度区分：

| 角色 | 识别依据 | 填到 |
|---|---|---|
| `zh_y` 支行-全年 | 网点列(D)全空 → 支行级；两张里累计数**大**的 | 支行 sheet **B**（金额）、**D**（单位） |
| `zh_m` 支行-当月 | 支行级；累计数**小**的 | 支行 sheet **C**、**E** |
| `wg_y` 网点-全年 | 有网点列(D)值 → 网点级；累计数**大**的 | 网点 sheet **B**、**D** |
| `wg_m` 网点-当月 | 网点级；累计数**小**的 | 网点 sheet **C**、**E** |

- 表头：**F 列 = 有效使用企业数-新口径（户）**，**K 列 = 薪酬代发金额（万元）**。数据从第 3 行起。
- **源表里没有任何日期标记**，所以全年/当月只能按**累计口径的大小**分：
  「当月 ≤ 全年」是定义决定的，脚本取 `sum_e`（各行认证企业数之和）大的为全年。
  两张累计数完全相同 → 脚本报错让用户人工确认，**不要猜**。
- 数值可能是带千分位的字符串（如 `'2,834.01'`）或带尾部制表符，脚本已统一处理。
- 支行级源表里的 `安徽阜阳分行应付利息计提（虚拟）`、`安徽阜阳分行电话银行（虚拟）`
  不在通报中，属正常，会在 `warnings` 里列出来。
- `problems` 非空 → **停下问用户**，常见：某级只有 1 张表、分不出年/月、
  有表格附件认不出是哪张源表。

### 通报模板（可选）与标题日期

- 发件人经常直接附**上一天已填好的通报**当版式（如 `薪管家通报0928.xlsx`）——
  脚本照用，`notices` 里会说明「模板用的是已填过数的通报」。
  **所有数据行都会按源表重写**，不会留旧数。
- 邮件没带模板 → 用技能内置的 `assets/template.xlsx`。
- **标题日期（「截至YYYY.MM.DD」）= 发信日期 T-1**，`--date` 可特殊注明。
  数据统计口径一般就是 T-1，所以 09-29 发来的信，标题写「截至2026.09.28」。
  发件人附的模板标题日期通常也是 T-1，但**一律以发信日期推算**，不沿用模板自带日期
  （模板可能滞后或写错）。
- 输出文件名默认 `薪管家通报{MMDD}.xlsx`（用同一个 T-1 日期），`--out-name` 可覆盖。
- 取不到发信日期时才退回模板自带日期，并在 `notices` 里说明。改完标题记得核对 `title`。

## 3 build：填表

```bash
$X build --workdir "/mnt/d/资料/ICBC/automations/20260929_薪管家"
```

- **通报两个 sheet 的四列**：
  - sheet「支行」B/C = 新增代发金额（全年/当月，万元），D/E = 新增有效使用单位（全年/当月，户）
  - sheet「网点」同上四列
  - 支行 sheet 第 12 行是「总计」，脚本按上面各行求和重算；网点 sheet 没有总计行。
- 按**网点名精确匹配**（忽略空白与全半角括号）。源表里没有的名字按 0 填并记 `warnings`。
- 金额保留 2 位小数，单位取整。
- **单元格格式一律沿用模板**，脚本只写值，不动字体/数字格式/列宽/合并单元格。
- 单位数是负数时通报里显示为负数，属正常。

## 4 文案

脚本按数据生成一段简短说明（`build` 的 JSON 里给 `text`，同时写入 `文案.txt`）：
全行全年/当月的代发金额与有效使用单位、全年与当月代发金额靠前的网点。

- **默认照用**，只允许微调措辞；所有数字一律用脚本结果。
- **改了文案就要重写 `文案.txt`**，`send` 发的是这个文件。

## 5 回信

```bash
$X send --workdir DIR            # 直接发
$X send --workdir DIR --dry-run  # 只看发给谁、正文是什么
```

- **收件人 = 原发件人 + 三个固定邮箱**（脚本 `FIXED_RECIPIENTS` 自动合并去重）：

  | 固定收件人 |
  |---|
  | `zhaili.fy@ah.icbc.com.cn` |
  | `zhangxiang.fy@ah.icbc.com.cn` |
  | `yaohongcheng.fy@ah.icbc.com.cn` |

  发件人本身就是这三个之一 → 只出现一次，共 3 个收件人；发件人是名单外的人 → 4 个。
  去重不分大小写。**不要手写收件人**，`--dry-run` 的 `to` 就是最终名单。
- 主题**统一为 `薪管家_YYYYMMDD`**（YYYYMMDD = 通报日期，如 `薪管家_20260928`），
  不再沿用原邮件主题。`--subject` 可覆盖。带 `In-Reply-To` 保持同一条会话。
- 正文 = 文案，附件只附通报 xlsx。用户已明确「直接发送，不用确认」。
- 发完把 `sent` 里的收件人、主题、附件名回报给用户。

## 6 已知事项（改动前先问用户）

- **「截至」日期 = 发信日期 T-1**（已按用户确认的规则），除非调用时用 `--date` 特殊注明。
  源表里没有日期，这是唯一的口径来源。发信日 = 收到日（当天跑当天发来的信）。
- **发件人习惯拿文件名当邮件主题**（实测 `网点 年`、`支行 月维度`），都不含「薪管家」，
  所以 `find` 大多会走「请示」分支。这是常态，不是故障。
- **年/月靠累计数大小区分**，是启发式。若某月为 0（如 1 月 1 日）导致两张表累计数相同，
  脚本会报错并要求人工确认，不会硬猜。
- **同一天若同时到达多封都含四张源表的邮件**，按日期取最新那封；
  多封并列时在 `notices` 里说明，以哪封为准由用户定。
  （实测 09-29、09-30 各一封，不是同一天。）
- 源表 sheet 名固定为 `工银薪管家数据增量表`。若行内改了表名或列序，
  `probe_xgj` 会认不出来 → 报 `unknown_files`，此时先问用户再改探针。
