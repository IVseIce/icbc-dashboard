## 源表结构

```
A1        全量客户场景攻坚成效图
A2/B2:C2  支行 | 养老代发场景（合并 2 列）| 薪管家代发场景 | …共 6 个场景
B3/C3     已落地 | 推进中      ← 每个场景都是这两列，共 12 列内容列
A4:A11    颍州 颍泉 颍东 界首 临泉 阜南 颍上 太和
A12       注释：标红为进度有变化项目
```

**合并单元格只有左上格有值**，其余是 `None`。所以定位场景列**不能先把表头向右填满再找**——
填满之后每个下标都成了真值，一个场景会被识别成两个（踩过，直接翻倍）。

## 口径：一个格子里数几个项目

单元格里一条项目一行，多条时用 `1.` `2.` `3.` 编号。切分规则（`ingest/scene.py::split_items`）：

1. 按编号切，编号正则 `(?<![\d.])([1-9])\s*[.、．]\s*(?!\d)`
   —— 前后都排除数字，否则「**颍东4家**加油站」里的 4 会被当成编号；
2. 编号前面还有正文（「已落地代发，其中…」）时，那段也单独算 1 条；
3. 没有编号就整格算 1 条。

**这套切法是对着成图 KPI 校准的**：落地 28 / 推进 23，与成图完全一致。
改切法一定会让数字对不上，改之前先看成图。

## 标红 → 金色文字

源表用**红色字体**表示"本期进度有变化"，成图里对应条目用**金色文字**（原图就是黄字）。

- 部分格子是**富文本**（同一格里一部分红、一部分不红），必须按 run 判断；
  只看单元格整体 `font.color` 会漏（`openpyxl.load_workbook(..., rich_text=True)` 才读得到）。
- `changed` 只标到具体那一条，不是整个格。

## 日期

`pbs.date_from_name`：认得 `20261024` / `2026-10-24` / `2026.10.24` / `10.24` / `1024` / `10月24日`…，
不带年的按当年。认不出**抛错让用户手填**（导入页会显示「数据日期」输入框）。

## 可视化（`pages/scene.js`）

**整页就是一张海报**，沿用分行原图的深红底 + 金字基调（取色：深红 `#5e060d` / 主红 `#a81325` /
亮红 `#b52230` / 金 `#ffd24a` / 暖金 `#f0b04a`）。原图本身不完美的地方只做了排版优化，
结构没动、**不放表格**：

- 顶部：金色大标题 + 一条金色分隔线 + 副标题；右侧 4 个金色大数字（场景 / 已落地 / 推进中 / 覆盖支行）
- 本期变化提示条（深红半透明 + 金边）
- 场景小图例（圆点 = 场景色，点击定位到该泳道）
- **6 条场景泳道**：左侧「✓ 已落地」、右侧「→ 推进中」，条目按支行分组，
  支行用金色胶囊；条目开头重复支行名会被去掉
- **同一场景 ≥4 家支行写同一句话时合并成一行**（数币 8 家都写「已落地数币代发」，
  堆 8 行是噪声），后面跟金色支行胶囊
- **本期有变化 = 金色文字**（照原图：原图是黄字，不是黄底）
- 页脚一行注脚

导出图片用 `html2canvas` 截 `#scBoard` 整块（2 倍图，底色 `#7d0d18` 兜底）。
通报中心里「下载成效图」会把同一份 payload 喂给 `pages/scene.js` 渲染再截，
**图和页面永远一致**，不另写一套排版。

## 已知坑

1. 合并单元格向右填满 → 场景列翻倍（见上）。
2. 富文本红字只读 `font.color` → 漏标，必须 `rich_text=True` 并按 run 判断。
3. 条目重复支行名（「颍上：颍上养老代发…」）—— 渲染时去前缀。
4. **标红→金色文字**，不是黄底：原图就是「黄字」，早期做成黄底与成图不一致（已改）。
5. `check_modules` 会要求通报有 `_base.xlsx` 母版，这条通报不产 Excel，
   所以 `report.IMAGE_ONLY` 里登记了它，校验器据此跳过。
