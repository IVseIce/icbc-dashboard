# 基保理（jg-income-jbl）

| 项 | 值 |
|---|---|
| 板块 / 分组 | 个人金融 / 增收 |
| 类型 | 数据模块（metric），**无通报**（用户 2026-11-02 明确：只做导入 + 可视化） |
| 数据源 | 《理财产品实时通报.xls》（基金 / 保险将来是各自的同类成表） |
| 粒度 | 支行 8 家 + 网点 40 个 |
| 频率 | 按「期」（一次营销活动 = 一期） |
| as_of | 标题里的日期（`11.1第41期…` → 2026-11-01）；手填优先，其次文件名 |
| 导入 | `viz.import_jbl` → `IMPORTERS['jbl_lc'] / ['jbl_fund'] / ['jbl_bx']` |
| 解析 | `ingest/jbl.py` |
| 视图 | `api.build_jbl`（三条线合成一个 `jbl` key）→ `BUILDERS['jbl']` / `LINE_OF['jbl']='jbl_lc'` |
| 页面 | `pages/jbl.js`，路由 `#/m/jg-income-jbl`（页签用 `?k=fund` / `?k=bx` 切） |
| 通报 | **没有**，`report.py` 里不登记 |

## 三条产品线各存各的

| 产品线 | 条线 id | 说明 |
|---|---|---|
| 理财 | `jbl_lc` | 已接入（catalog 的 `as_line`） |
| 基金 | `jbl_fund` | 解析器一样，等源表 |
| 保险 | `jbl_bx` | 解析器一样，等源表 |

三条线互不覆盖（同一天三条都能导），`api.build_jbl` 把三条合成一个结构：
`{ok, kinds:[...], lc:{...}, fund:{...}, bx:{...}}`，每条线内部是
`{branches, nets, trend, branch_hist, kpi, period, periods}`。
`JBL_LINE_KEYS` 让三条真实条线都映射到视图 key `jbl`，前端的「数据截至」才认得出。

## 源表形态与口径（**用户拍板：成表原样取，不重算**）

一份工作簿通常 5 张子表：

```
支行通报   ← 要    支行 | 39期销量 | 40期销量 | 本期销量 | 每期目标 | 达成率 | 重点基金 | 合计
网点通报   ← 要   （空）| 网点  | 39期销量 | 40期销量 | 本期销量 | 重点基金 | 合计
支行草稿   ← 忽略（中间产物）
网点草稿   ← 忽略（中间产物）
40期      ← 忽略（个人明细产品指标查询表，按日）
```

- **不重算**：`合计`、`重点基金` 都是源表原值。源表自己就对不上（支行表「合计」列合计 138.05
  与网点表一致，但**逐支行分摊完全不同**；39 期支行合计 667.60 vs 网点合计 675.60，差 8.00）。
  按用户要求原样呈现，不做校验修正、不报警。
- **期数不写死**：列名按 `(\d+)期销量` 解析，本期是第几期从标题的「第N期」取；
  标题里没有时退回"列里最大期数 + 1"。
- **期数会重叠**：一张表带 3 期（39/40/本期 41），下次是 41/42/本期 43。
  `api.build_jbl` 把所有快照的 `period_totals` 按期数合并，**同一期以更晚导入的为准**
  （`_upto` 按 `as_of` 升序，直接覆盖写）。
- 单位**万元**。

## 网点归属（踩过）

源表「网点通报」的**支行列是错的**：太和人民路标成颍州、界首科创标成颍州、
阜南三家标到别的支行……按它聚合和「支行通报」完全对不上。
所以统一用 `report/assets/jbl_nets.json`（40 个实体网点 → 支行，
从 `pb_nets.json` 复制，与私银/一卡一户同一套口径）；映射里没有的网点才信源表那一列。

## 识别规则（内容优先，名字兜底）

`ingest/jbl.py::_find_header` 扫每张子表前 8 行找"字段行"：
同时出现「网点」或「支行」`+` `N期销量`/`本期销量` 之一。

- 有「网点」列 → 网点表（首列无表头的「支行列」取第 0 列）
- 否则 → 支行表

草稿表与通报表**表头一模一样**，靠表头分不出来 → 同结构多张时**优先子表名带「通报」的**，
并在 `_files` / `_notes` 里注明；只有草稿时用草稿。

## 导入时的校验

- **产品线把关**：源表标题里认出的产品线（理财/基金/保险）与当前条线不符 → 直接报错，
  避免把基金表传进理财线。
- **缺表也收**：只导支行表或只导网点表都能成功，`_notes` 里提示"另一张表可再导一次"；
  同一天补导时 `ingest.jbl.merge()` 从旧快照把缺的那张带过来。

## 已知限制

- **没有通报 / 没有 Excel 导出**（用户明确不需要）。
- 基金、保险两条线只有解析器，没有真实源表可验证；标题里认不出产品名时默认按理财处理。
- 源表自身的不一致（合计列分摊、39 期差 8 万）按用户要求**原样保留**，页面不做提示。

## 改这个模块时先看

1. `src/ingest/jbl.py` 顶部常量（`KIND_LINE` / `FIELD_RX` / `TITLE_PERIOD_RX`）
2. `src/report/assets/jbl_nets.json`（网点归属；换网点口径要改这里）
3. `src/server/api.py` 的 `JBL_LINES` / `build_jbl` / `_jbl_one`（按期合并逻辑在 `_jbl_one`）
4. `src/web/assets/js/pages/jbl.js`（三个页签；切页签必须每次重画后重新绑事件）
