# 一卡一户（jg-customer-yika）

| 项 | 值 |
|---|---|
| 板块 / 分组 | 个人金融 / 增客 |
| 类型 | 数据模块（metric） |
| 数据源 | ① 社保卡：中国工商银行借记卡发卡统计报表（每日一张）<br>② 个人养老金：多日期并排的开户统计表（一份含几十个日期） |
| 粒度 | 网点（40 个），支行 8 家小计，分行合计 |
| 频率 | 日（周五~周日合并成一块，周日出通报） |

| 导入 | `viz.import_yika` → `IMPORTERS['ykh']` |
| 视图 | `api.build_yika` → `BUILDERS['yika']` / `LINE_OF['yika']='ykh'` |
| 页面 | `pages/yika.js`，路由 `#/m/jg-customer-yika` |
| 通报 | `report.build_yika` / `yika_xlsx`，`CAT_OF['yika']='jg'`，母版 `yika_base.xlsx` |
| 口令可见 | 个金口令、管理员 |

## 两个产品、十个数字

成表 `通报` 子表的结构（40 个网点 + 8 行支行小计 + 1 行分行合计）：

| 列 | 含义 | 算法 |
|---|---|---|
| C | 社保卡 当日开户 | 累计(当日) − 累计(前一日) |
| D | 社保卡 当日目标 | **固定值**（每网点 4 或 6，合计 198） |
| E | 社保卡 日平台达成率 | C ÷ D |
| F | 社保卡 本周开户 | 累计(当日) − 累计(上周末) |
| G / H / I / J | 个人养老金（结构同 C/D/E/F） | 同上 |
| K | 当日合计完成率 | (G + C) ÷ (D + H) |
| L | 合计周任务完成率 | (J + F) ÷ (H × 2 × 6) |

- `H × 2 × 6` 里的 **6 是固定口径**（周任务按 6 个计分日折算），来源不明但用户确认沿用。
- **合计行注意**：成表最后一行 `阜阳分行` 的公式是 `=SUM(C4:C51)/2`（因为上面 8 行小计已经加过一遍），
  所以是"8 个支行小计之和 ÷ 2"= 40 个网点之和。**直接算网点之和即可，不要真的去除 2**。

## 「累计」到底是什么（最容易搞错的地方）

不是户数，是**年内累计新增数**：

- **社保卡**：`柜台新增卡数量（本年累计）` + `批量开户新增卡（本年累计）`
- **个人养老金**：`本年新增`

⚠️ 养老金表里还有一列 `累计开户数`（存量，含去年及以前）。**用它相减跨年就错**，
成表用的是 `本年新增`。

## 日期口径

    数据块 = 周五 + 周六 + 周日（周日出通报）；其余日子各自一块
    当日    = 出通报那天（周日代表 周五~周日 三天合计）
    前一日  = 上一个数据块的末日。周日 → 周四；周二 → 周一；周一 → 上周日
    上周末  = 本周（周一~周日）开始前的那个周日

- **周五、周六不出通报**，只在周日合并出（用户确认）
- **周一**：前一日 = 上周末 = 上周日，本周新增 == 当日新增，只需 2 天数据
- 通报标题：周日出 `10.23-10.25`，其他日子出 `10.26`；文案里写 `10月23-25日`

实现在 `ingest/yika.py`：`block_of()` / `prev_block_end()` / `week_start_sunday()` / `plan_dates()`。

## 存储：按日存累计值

`ykh_sb`（社保卡）与 `ykh_yl`（养老金）是**辅助条线**，每条一个日期一行，
payload 只有 `{cum: {网点: 累计}, parts: {...}, grand: [...]}`。真正的成表快照存在 `ykh`。

好处：

- 每天只导 1 张社保卡 + 1 张养老金就够了，不用凑三张表
- 养老金那种多日期表**一次导入能把 36 个日期全存进来**，等于自动补历史
- 出通报时按需要的三个日期从库里取，缺哪天直接报"社保卡缺 2026-10-22"

`grand` 存的是源表末行「合计」（含"安徽阜阳分行运行管理部"这类非网点机构），
导出成表的「合计」行要用它——40 个网点之和会比它少 2 张（运行管理部那 2 张）。

## 网点名三处不一致（踩过）

| 来源 | 写法 |
|---|---|
| 成表母版 / 养老金表 | `界首支行营业室` |
| 社保卡源表 | `阜阳界首支行营业室`（多"阜阳"前缀） |

- 归一函数：`ingest/yika.py::_norm()`（去掉 `安徽阜阳分行` 或 `阜阳` 前缀）
- 匹配：`_lookup()` 精确 → 去前缀 → 后缀唯一匹配
- 社保卡源表还有一行 `安徽阜阳分行运行管理部`，**不是网点**，别计入 40 个

## Excel 母版 `yika_base.xlsx`

来自用户给的成表 `10.08一卡一户.xlsx`，用 `scripts/build_yika_assets.py` 清数据生成。

⚠️ **清数据不能整段清空**：社保卡 `F/J`、养老金 `Q/R` 是公式，养老金 `G/M` 列是网点名。
第一版把这些一起清了，辅助 sheet 全成空白。现在只清"累计值"那几列。

条件格式（母版自带，**别手工涂色**）：

| 列 | 规则 |
|---|---|
| E / I（日平台达成率） | ≥1 红色字；=0 绿色字 |
| F / J（本周开户） | 前 3 名红底；=0 绿底 |
| K / L（两个完成率） | 前 3 红底；后 3 绿底 |

多个 0 时**都是绿的**（这是用户要的：大家都 0 就都标绿，不是按名次挑）。

## 通报文案

严格照用户给的标准模板，`report.build_yika()['text']`。要点：

- 期间：`10月23-25日`（同月省略后一个"月"），单日 `10月26日`
- 支行靠前取**前二**（按当日合计完成率）
- "不足 X%"：取**最低的一家**，阈值向上取整到 5 的倍数；最低两家都不足 25% 时两家一起报
  （`_low_threshold()`）
- 网点叫法 = 支行名 + 网点名（`_short_net()`）：`颍州城建`、`临泉姜尚`，
  **不能只去掉"阜阳""支行"**，否则变成"城建""姜尚"，看不出哪个支行
- 两项均无业绩 = 社保、养老**日平台达成率都 ≤ 0**（一负一正不算）

已与用户给的模板**逐字比对一致**（1023-1025 那期）。
