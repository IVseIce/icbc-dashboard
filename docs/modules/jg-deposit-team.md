# 经理队伍（jg-deposit-team）

| 项 | 值 |
|---|---|
| 板块 / 分组 | 个人金融 / 增存 |
| 类型 | 数据模块（metric），**一块模块两块内容**（财客 / 远维，页面页签切换） |
| 数据源 | 两个官方工作簿的**明细子表**：`财客明细`（88 列）、`远维明细`（83 列）。可只导一个 |
| 粒度 | 财客：支行 8 + 网点 40 + 经理 49；远维：支行 8 + 经理 10（**无网点**） |
| 频率 | 不定期（累计口径，较年初） |
| as_of | **源表里没有日期**，从文件名识别（复用 `ingest.pbs.date_from_name`）；认不出让用户手填 |
| 导入 | `viz.import_team` → `IMPORTERS['team']`；`DATE_ARG_LINES` 含 `team` |
| 视图 | `api.build_team` → `BUILDERS['team']`、`LINE_OF['team']='team'`；`team_kpi()` 供首页 |
| 页面 | `pages/team.js`，路由 `#/m/jg-deposit-team`（`?b=yw` 切远维） |
| 通报 | **一条**：`report.build_team`（`CAT_OF['team']='jg'`），导出走 `ck_xlsx` / `yw_xlsx` 两个 key；`BASES_OF['team']=('ck','yw')` |
| 母版 | `src/report/assets/ck_base.xlsx` / `yw_base.xlsx`，由 `scripts/build_team_bases.py` 从官方成表生成 |
| 口令可见 | 个金口令、管理员 |

## 怎么认出"这是哪一块"（0.1.8.3 起按表头，不靠子表名）

`ingest/team.py::_sniff_sheet()` 对工作簿里**每一张**子表打分，四道关：

| 关 | 判据 | 挡掉谁 |
|---|---|---|
| 1 尺寸 | ≥5 行、≥40 列 | `支行通报数据`、`Sheet3`、`VLOOK` |
| 2 三行表头 | 第 2、3 行**按合并区展开**后都 ≥30 格有内容，且第 2 行无任何数值 | `计算１` / `计算`（同数据、表头压成一行） |
| 3 表头签名 | 必含 `分行/网点/客户经理姓名/储蓄存款/期缴保险`（财客）；远维必含 `支行/客户经理姓名/储蓄存款` 且**不含** `网点/期缴保险/分行` | 其他表 |
| 4 名字兜底 | 前三关都不中时，才用 `财客明细`/`远维明细` 这两个名字 | — |

所以下面这些情况都能正常导入（都实测过）：

- 子表被改成 `乱七八糟` / `数据1` / `Sheet1`
- 两张表塞进同一个工作簿（会把两块都收下）
- 两个文件一次传（按文件名日期取较晚的）

对不上时会把判断依据写进报错，而不是只说"找不到子表"。

## 源表结构（别自己推，都在这里）

同一份工作簿里除明细表外还有三张中间表，**都不读**：

| 子表 | 是什么 | 我们怎么用 |
|---|---|---|
| `财客明细` / `远维明细` | 真源数据，3 行表头 | **只读这张** |
| `计算１` / `计算` | `财客明细` 换了表头的同一份数据（49×88 逐格一致） | 忽略 |
| `ＶＬＯＯＫ` / `VLOOK` | 按支行聚合的透视结果 | 忽略（我们自己聚合） |
| `Sheet3` / `Sheet1` | 空壳/临时 | 忽略 |

`ingest/team.py` 里 `CK_COLS` / `YW_COLS` 是「字段 → 列号」映射，导入时用**三行表头合并后的路径**
逐列校验（`CHECK` 里抽查关键列），源表加列/挪列会直接报错，不会静默取错数。

远维明细末尾有一片**隐藏的临时名单区**（15 行起，只有姓名 + 网点名，没有支行）——
解析时按"支行列为空"跳过；母版里也已删掉这部分行。

## 口径（2026-10-29 对着成表逐格验算）

1. **支行/网点聚合**：`总得分`、`营销通常态化`、`营销通限时` 取**平均**；其余全部**求和**
2. **单位**：明细是万元。财客成表把存款/非存/理财都换成**亿元**（÷10000）；
   远维成表里存款/非存换亿，**理财仍是万元**
3. **50 万以上客户**：表头写「万户」，值其实是**户**——成表照抄，不换算（`3145` 不是 `0.3145`）
4. **红绿**：前二红、后二绿，**按名次**不按正负（页面与 Excel 同源）
5. **排名**：Excel `RANK` 语义——降序、并列同名次并跳号
6. **合计行**：名次列写 `－`（固定标签），其余列按上面 1、2 的规则算全行合计
7. **绝不四舍五入**：快照里存 double 原值。成表对账是逐格比 double，
   早先 `round(x, 6)` 导致 63 处差异（症状：`92.2885807957933` vs `92.288581`）

## 远维成表 R~V 五列的官方错误（我们已修正）

官方 `支行通报数据` 的 R~V 用 `VLOOKUP(B, VLOOK!$A:$Y, 14~18, 0)`，但远维的透视表比财客
**多了一列「社保卡存量」**，序号没跟着改，于是整体错位一格：

| 列 | 表头写的 | 官方取到的是 |
|---|---|---|
| R | 社保卡 净增 | 社保卡**存量** |
| S | 养老金 净增 | 社保卡**增量** |
| T | 借记卡绑卡 净增 | 养老金**增量** |
| U | 贷记卡绑卡消费 净增 | 借记卡绑卡**增量** |
| V | 信用卡纯消费 净增 | 贷记卡绑卡消费**增量** |

「贷记卡纯消费增量」这一列官方压根没引用。**用户 2026-10-29 确认按表头取数（与财客对齐）**，
所以导出与官方原件在这 5 列上不同 —— 对账脚本用 `SKIP_CELLS['yw']` 跳过这几格。

## 通报（一条 + 两个下载按钮）

用户 2026-10-29 明确要求：**不拆成两条通报**。所以：

- `report.build_team()` 把两块合成一条，`text` 是**整篇**（开场白 + （一）财客 + （二）远维），
  一次「复制文案」就是完整通报
- 返回 `downloads: [{key:'ck', name:'下载 财客 Excel（10.21）'}, {key:'yw', …}]`，
  前端 `report.js::paintDownloads()` 按这个**动态渲染按钮**（以前是两个写死的 id）
- 表格四张：`财客·支行 / 财客·客户经理 / 远维·支行 / 远维·客户经理`，标题都带块名和日期
- 只导了一块时：只出那一块，并在页面顶部提示"仅导入了一块：还没有「远维」的数据"
- `report.build_ck` / `build_yw` 仍然保留（单独取一块数据时用），但**不注册进 `BUILDERS`**

## 文案

`report._team_text()` 一份一段，句式照定稿抄：

- 开场白「各支行：现将…通报如下：」**只放在（一）财客**里，两份按顺序粘起来才是完整通报
- 前二/后二一律按**排序后切片**取（HANDOFF 8.2-21），不按正负筛
- 数字格式：得分 2 位带「分」、存款/非存 2 位带「亿元」、客户 0 位带「户」、融e借/卡分期带「万」
- **不带千分位**（定稿是「界首(1478户)」）
- 财客「卡分期任务完成率」这句按用户要求**沿用原措辞**，虽然数值其实是增量

## 已知坑

- 两份文件**可以只导一个**：`team.merge()` 会把同一天之前导过的另一块带过来，
  并在页面「导入说明」里写清是"沿用"还是"本次只导了X"
- 同日重复导入 = 覆盖该块，不会产生两行
- 母版里 J 列（营业贡献当前）是**隐藏列**，J/K/L 三列成表本来就不填，别去取消隐藏
- 官方成表 A14 是当期手写备注（"阜南支行因远维更换…"），**按用户要求导出时留空**
