## 0. 术语速查（你提到不太熟的概念）

| 概念 | 白话 |
|---|---|
| 指标字典 | 每个指标的定义、口径、单位、来源、责任人写在一张表里，避免“同名不同义” |
| ODS / DWD / ADS | 数仓分层：ODS=原始落地；DWD=清洗后的明细；ADS=给页面用的汇总。我们简化为“原件 → 标准化事实表 → 页面视图” |
| 星型模型 | 一张事实表（数值）+ 若干维表（日期/机构/指标），查询灵活、不重复 |
| 幂等 | 同一个文件重复导入，结果不变、不产生重复数据 |
| RBAC | 按角色授权（谁能看、谁能传），后续账号系统用 |
| 快照 | 某个日期的一份数据，日期是主键的一部分 |

## 4. 信息架构

```
首页 /#/
├─ 全局日期选择（默认最新），六专业卡片（个金 / 个贷 / 银行卡 / 网金 / 私银 / ?）
│   └─ 个金：增存 · 增客 · 增收 · 增贷（占位）
│   └─ 网金：线上服务 · 数币 · 企微
├─ 重点项目区：全量客户拓展 / 企微 / 五卡唤醒 / 挑战100名客户回访
└─ 数据时点 / 完整度提示

模块页 /#/m/<module>      例：增存-定期存款
├─ KPI + 趋势 + 支行排行 + 网点排行
└─ 明细表（全屏）+ 导出

重点项目页 /#/p/<project>  例：五卡唤醒
├─ 进度/目标/完成度（有则显示）
└─ 关联模块数据（同一份数据可被多个模块引用）

通报中心 /#/report
├─ 选条线 + 日期 → 表格预览（同现有通报版式）
├─ 文案（可编辑、可复制）
└─ 下载 Excel / PDF / PNG

数据管理 /#/upload
├─ 第一层：专业/大类 → 第二层：小模块（如 个金/增存/定期存款）
├─ 拖拽上传 → 识别 → 校验 → 归档 → 入库
└─ 上传记录（谁、何时、哪个模块、成功/失败）
```

## 5. 数据模型（建议迁到 SQLite）

```
dim_org      (org_code, org_name, branch_code, branch_name, level[支行/网点], active)
dim_module   (module_code, parent_code, name, level, professional, priority, status)
dim_metric   (metric_code, name, module_code, unit, direction, definition, owner)
fact_metric  (date, org_code, module_code, metric_code, value, source_file, ingest_id)
ingest_log   (id, file, sha1, module_code, data_date, rows, ok, error, uploaded_by, created_at)
```

- 日期是主键的一部分 → 天然支持“选某天看某天”；
- 模块与指标分离 → 同一份数据可挂到多个模块（如企微同时属于网金和重点项目）；
- 指标字典 → 页面标题/单位/口径说明都从这里取，避免写死；
- 原始文件与标准化结果都留档，可回溯。

现状是 JSON 快照（38 个），迁移脚本可以一次性灌入 SQLite，保留原始层。

## 6. 上传与权限

- **两层选择**：专业/大类（个金、网金…）→ 小模块（增存-定期存款、增客-代发…）。
- 文件识别：按模块登记的“指纹规则”校验（列名/标题/日期），不匹配直接拒绝并说明原因。
- 校验：网点/支行名映射、合计校验（与文件内合计行比对）、日期校验、重复文件（sha1）幂等。
- 权限：先做“上传人选择（姓名）+ 记录留痕”，账号体系（AD/LDAP）后置。

## 7. 呈现与下钻

- 全局日期选择器：日频数据按日、周频取当周、月频取当月；无数据时提示“该日无数据，最近为 X 日”。
- 每个模块统一四层：KPI → 趋势 → 支行 → 网点，表格支持全屏与导出。
- 头尾突出：排行默认“前 N + ⋯ + 后 N”，可切换“全部”。

## 8. 通报中心

- 模板来源：现有 5 个 icbc-* 技能的成品（表格版式 + 文案定稿）。
- 生成：选日期 → 预览 → 一键复制文案 / 下载表格。
- 导出：
  - Excel：openpyxl（保留格式、条件格式可选）
  - PDF / PNG：本机 Chrome 无头打印（需确认服务器有 Chrome）；备选 weasyprint / 前端截图
- 文案模板可配置（放 `data/templates/`），改措辞不用改代码。

---

## 9. 技术栈与目录

- 后端：Python 标准库 HTTP + `sqlite3`（无额外服务）；
- 前端：原生 ES Modules + ECharts（已内置，离线可用）；
- 依赖：`openpyxl`、`xlrd`（+ 导出用 `openpyxl` 已有；PDF/PNG 复用 Chrome）。
- 目录（在现有基础上扩展）：

```
src/
  server/        路由 + API（模块化：每个模块一个 router）
  domain/        指标、机构、模块注册表（YAML/Python 配置）
  ingest/        各模块的识别与入库适配器
  report/        通报模板与导出
  web/           前端 pages/*（每模块一个页面文件）
data/
  raw/<module>/<date>/   原件
  db/dashboard.db        SQLite
  templates/             通报模板
```

新增一个模块 = 加一份配置 + 一个 ingest 适配器 + 一个页面文件，其余导航/日期/导出自动继承。
